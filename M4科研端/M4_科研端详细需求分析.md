# 智学数研 M4 科研端详细需求分析与设计基线

> 版本：v2.0｜日期：2026-08-21｜状态：方案 A 已确认  
> 本文档是科研端产品、交互与底层实现的需求单一事实源；字段级契约以《M4_API接口文档.md》为准。  
> **关键变更：Lean4 已确定在后端运行与构建，提升为一期正式能力，不再是“二期火种”。**

# 1. 摘要

科研端采用“任务流驱动的研究工作台”，服务数学建模学生、教师科研人员和数学研究人员。系统把文献发现、知识整理、数学验证、Lean4 形式化、论文写作、论文初审、教育研究与成果回流放在同一项目上下文中。核心价值不是替代科研判断，而是把每个关键结论变成可定位、可复查、可重复运行的证据。

系统提供三种运行等级：完整后端与星辰工作流协同、后端纯本地引擎降级、无服务时的浏览器本地降级。用户始终能看到执行路径、证据来源、未运行能力及恢复办法。

# 3. 背景与问题

## 3.1 保留的 v1.0 资产

- 四态验证语义：`pass / unverifiable / counterexample / formal_pending`。
- LLM 负责解释和草案，确定性引擎负责判定。
- 初审五层漏斗、页码证据和作者/评委双视角。
- LaTeX 三栏工作台、SyncTeX、Tectonic、Pandoc 和模板库。
- 文献三源检索、引用核验、个人库、教育数据分级。
- 学生端 F14、教师端 F12 与科研端共用验证/评审内核。

## 3.2 必须修正

1. 旧 IA 按 F1–F10 平铺工具，项目上下文反复丢失。
2. Lean4 被写成可砍演示，与后端正式构建决策冲突。
3. 星辰工作流和本地引擎缺少统一路由、幂等、追踪与恢复契约。
4. “本地降级”没有逐能力说明能做、不能做和可信度。
5. 缺少运行历史、证据账本和复现包，无法回答“做过什么、为何可信、能否重跑”。
6. 三端联动偏入口跳转，缺少对象级权限、版本、审批与撤回。

定位：**把数学结论送入 SymPy/Lean4，把引用送入多源核验，把教育数据送入可复现分析，再把全部证据带回论文。**

## 4.4 真实科研困难

科研软件、数据管理、引用实践和 Lean 使用研究共同指向八类问题：信息过载；PDF/笔记/代码/公式/数据/论文碎片化；缺运行环境与参数导致不可复现；引用错误与幻觉；数值、符号、形式化证据混淆；排版中断研究思路；协作责任不清；Lean 同时要求数学、语法、策略、依赖知识。

因此产品必须提供项目上下文、来源级证据、运行历史、数据可迁移、渐进披露、失败恢复和人工终审，而不是只增加聊天框。

# 5. 目标、指标与非目标

## 5.1 目标

- 从研究问题进入任务，而不是先选择工具。
- 关键结论可追到输入、执行器、版本、日志和原文。
- Lean4 后端稳定、隔离、可取消地构建并返回结构化诊断。
- 星辰或外部 API 不可用时，本地确定性能力仍能闭环。
- 三端围绕同一资产协作但不突破权限与隐私。

## 5.2 Gate 指标

| 指标 | 标准 |
|---|---|
| 首个“文献→验证→写作引用”闭环 | 新用户中位数 ≤15 分钟 |
| 结果可追溯率 | 100% 有 executor/version/input_hash/evidence |
| Lean 已接受证明误报 | 0；仅 kernel 接受可标 verified |
| Lean 热缓存构建 | 甜区 P95 ≤20s；冷启动 P95 ≤90s |
| Lean 取消 | P95 ≤2s 进入 cancelling，≤10s 清进程树 |
| 初审事实性误报 | 金标准集 ≤5% |
| 引用核验覆盖 | 100% 引用有状态，不静默遗漏 |
| LaTeX 模板编译成功 | ≥99% |
| worker 重启恢复 | ≥99% 非运行中任务可恢复或明确终止 |
| 降级透明度 | 100% 结果显示模式与缺失能力 |
| 教育隐私 | k<20 100% 拒绝；L2 100% 审批、水印、审计 |
| 无障碍 | 关键流键盘可达；状态 100% 非纯颜色表达 |

## 5.3 非目标

- 不代做竞赛题，不生成可直接提交的整篇论文。
- 不判断创新性、最终排名、录用或抄袭结论。
- 不把抽样或 SymPy 化简称为形式化证明。
- 不在浏览器进行 Lean4 全量构建；离线可编辑/导出，但只能标 formal_pending。
- M4 不做任意 GPU 训练平台、多人实时协同或通用 LIMS。

# 6. 用户与端到端任务

核心用户：数学建模学生、指导教师/教师科研人员、数学科研人员、评委/审稿辅助角色。

六条任务流：

1. **发现**：项目→问题→多源检索→纳入/排除→笔记→研究脉络。
2. **验证**：声明→规范表达/假设确认→五能力→必要时升级 Lean→保存证据。
3. **形式化**：自然语言→Lean statement 草案→人工确认→后端构建→目标/诊断→修改 tactic→kernel 接受。
4. **写作**：模板/导入→LaTeX→文献/验证/图表→编译→逐条润色→复现包。
5. **评审**：批量→五层检查→人工关注队列→页码证据→反馈→辅助报告。
6. **教育研究**：匿名数据产品→隐私预检→快照→统计→图表/字典→论文。

# 8. 功能需求

## 8.1 项目与证据账本（P0）

- 项目包含问题、阶段、成员、资产、任务、运行、证据和活动。
- Evidence 含类型、来源对象、原文范围、输入哈希、执行器、版本、run、可信等级和撤回状态。
- 报告、公式、引用、图表和 Lean 证明均可加入账本。
- 证据追加版本；纠错用 supersede/retract，不覆盖历史。
- 可导出 manifest、数据字典、参数、环境锁、代码、证据索引和许可证。

## 8.2 文献与知识库（P0）

- 关键词/自然语言/DOI/题名/作者/年份检索；完整模式聚合 Crossref/OpenAlex/S2。
- DOI 优先去重，次用规范题名+首作者+年份；纳入/排除必须记录理由。
- GROBID/Docling 输出 DocumentIR，段落保留页码、范围、层级和解析器版本。
- 核验状态：`verified_exact / verified_fuzzy / conflicting / not_found / source_unavailable / local_only`。
- `not_found` 不等于论文不存在；来源不可用必须单列。
- 本地库支持 BM25、标签、笔记、PDF 标注和编号证据检索。

## 8.3 数学验证（P0）

- 支持 LaTeX、纯文本、论文选区和 JSON；运行前确认规范表达、变量、定义域、单位和假设。
- 五能力独立执行：数值复算、符号等价、量纲、不等式/边界、反例。
- 四态：通过、未能自动验证、发现反例、形式化待确认。
- 反例带代入值、约束检查和复算；不满足前提的反例作废。
- 可携带全部上下文升级 Lean4。

## 8.4 Lean4 形式化（P0，后端正式）

- 固定 `lean_toolchain`、Mathlib commit、依赖与镜像摘要。
- 从空白、模板、数学验证或论文声明创建。
- 自然语言只生成 statement 草案；用户确认后才能证明搜索/构建。
- 支持 `check/build/run_tactic/cancel/retry`。
- 状态：`queued/preparing/elaborating/awaiting_statement_confirm/running/succeeded/failed/timed_out/out_of_memory/cancelled/infra_error`。
- 区分语法、类型、未闭合目标、sorry、超时、OOM、依赖、基础设施和 kernel 接受。
- `sorry/admit` 或未闭合目标绝不能标通过。
- 显示目标栈、诊断行列、定理、日志、缓存命中和资源。
- 沙箱无网络、只读依赖、临时写、非 root、进程树取消。

## 8.5 LaTeX 写作（P0）

- 文件树、CodeMirror、PDF 和日志四区可调。
- Word/MD/Excel/图片公式先预览结构 diff，确认后写入。
- 固定 Tectonic bundle，无网络、项目锁、缓存、输出白名单。
- SyncTeX 双向定位；失败显示原因。
- 引用从项目库插入，冲突 key 写入前处理。
- 润色逐条显示原文/建议/理由/风险，不提供全文一键重写。
- 翻译保护数学环境、命令、citation key 和 label/ref。
- 导出 PDF/TEX/Bib/源项目/复现包。

## 8.6 初审（P0）

- 至多 50 篇；单篇失败不拖批次。
- 五层：格式、引用、符号/量纲、数学验证、语言。
- 按“需人工关注”排序，并固定显示“不是论文排名”。
- 问题项含层、严重度、置信、页码、原文、检查器和证据。
- 作者可见建议；评委默认不下发建议字段。
- 不判断创新性、录用和最终评分。

## 8.7 教育研究与三端联动（P0）

- 科研端只查询授权数据产品，不直连学生业务库。
- L1 聚合默认；任一切片 k<20 拒绝。
- L2 去标识个体数据需用途、伦理承诺、指导教师+管理员双签、时效、水印和审计。
- 图表保存数据快照与参数；导出 PNG/SVG/PDF/TikZ/PGFPlots。
- 学生可提交推导；教师可发布匿名教研任务；科研端可申请回流已验证题、方法卡、形式化样例。
- 跨端发布使用副本+来源链接+版本；撤回通知消费端。

## 8.8 科研助手与星辰（P1）

- 助手只在项目上下文工作，回答带 evidence 编号。
- 通过 `WorkflowAdapter` 接入，业务不得绑定某个工作流私有字段。
- 星辰队友维护内部节点；科研端登记 key、版本、schema、超时、回调。
- 工作流输出进入待确认草案；引用真伪、SymPy、Lean kernel、隐私规则不得由工作流替代。
- 翻译、结构提取、语言建议、形式化草案可走星辰；不可用时切本地规则/模型。

# 9. 底层实现方案

## 9.1 架构

```text
Web：Workspace / Evidence UI / Run Center / Capability Registry / IndexedDB
  ↓
Research API/BFF：AuthZ / 领域服务 / Run Orchestrator / Execution Router / Evidence Ledger
  ↓
Workers
  light：规则、格式化、元数据
  document：GROBID / Docling / OCR / 索引
  compute：SymPy / 统计 / 图表 / Pandoc / Tectonic
  formal：Lean4 / Mathlib / LeanDojo adapter
  workflow：星辰调用、回调校验、本地生成适配
  ↓
PostgreSQL / Object Storage / Redis Queue / Search Index / Metrics
```

## 9.2 统一 Run 模型

```json
{"run_id":"run_01...","project_id":"prj_01...","kind":"lean.build","requested_mode":"auto","resolved_mode":"full","status":"queued","input_hash":"sha256:...","executor":{"name":"lean4","version":"locked","image_digest":"sha256:..."},"capabilities_used":["backend","lean","mathlib_cache"],"missing_capabilities":[],"parent_run_id":null,"trace_id":"tr_01..."}
```

- `Idempotency-Key + kind + input_hash` 防重复。
- 状态只由 orchestrator 迁移；worker 追加事件。
- 事件：queued/preparing/progress/log/artifact/awaiting_confirm/completed/failed。
- SSE 用 `Last-Event-ID` 补流；不支持 SSE 时轮询同一事件序列。
- 重试生成新 run，用 parent 关联；历史不覆盖。

## 9.3 路由规则

1. 读取 `/capabilities` 与浏览器能力。
2. 按任务 `required_capabilities` 排除不满足路径。
3. 完整可用：后端确定性执行器 + 必要星辰/外部源。
4. 工作流/外部源不可用：后端纯本地引擎，标 `local_engine`。
5. 后端不可用：浏览器本地能力，标 `browser_local`。
6. 无可信执行器：保存草案/导出包，状态 `unavailable`，不伪造结果。

## 9.4 Lean4 后端

1. 创建 run，源码/manifest 做大小、路径、依赖白名单校验。
2. formal worker 在临时工作区只读挂载固定 Lean/Mathlib，用户文件单独写入。
3. 缓存键包含 toolchain、Mathlib commit、manifest、导入闭包和源码哈希。
4. check 使用诊断服务；build 使用精确 Lake target；tactic 走受控 REPL。
5. 日志转结构化 URI/range/severity/code/message。
6. 超时先取消再杀进程树；容器销毁；只存白名单产物。
7. 成功必须构建成功、无项目禁止的 sorry/admit，且 kernel 接受。

## 9.5 文档、引用与安全

- `DocumentIR`：document→pages→blocks→spans，span 带 bbox/offset/section。
- 题录合并保留 `source_records[]`，不覆盖冲突；精确 DOI 优先，模糊保留分数。
- 本地至少 BM25；向量检索是增强。引用编号绑定 `document_id+span_id+parser_version`。
- 重任务低并发、短任务高并发；上传检查魔数、大小、压缩炸弹和路径穿越。
- Lean/TeX/Pandoc 沙箱无网络、非 root、只读依赖、临时目录。
- 日志不写论文全文、学生明细、token 或密钥。
- 监控队列、阶段耗时、缓存、解析失败、外部源可用、降级率和取消清理。

# 10. 不降级与降级设计

## 10.1 等级

| 等级 | 条件 | 标签 |
|---|---|---|
| FULL | 后端及所需执行器可用；需要时星辰/外部源可用 | 完整模式 |
| LOCAL_ENGINE | 后端可用，星辰或外部 API 不可用 | 本地引擎 |
| BROWSER_LOCAL | 后端不可达 | 浏览器离线 |
| UNAVAILABLE | 没有可信执行器 | 暂不可运行 |

## 10.2 能力矩阵

| 能力 | FULL 不降级 | LOCAL_ENGINE | BROWSER_LOCAL | 诚实边界 |
|---|---|---|---|---|
| 项目/笔记 | 同步、权限、版本 | 同 FULL | IndexedDB、操作队列、JSON 导出 | 离线不显示已同步 |
| 文献检索 | Crossref+OpenAlex+S2 | 本地库/缓存/用户导入 | 本地题名/作者/全文 | 未查外部不标 exact |
| PDF 解析 | GROBID+Docling | 服务器本地解析 | PDF.js 基础文本/页码 | 标 basic_parse |
| 引用格式 | CSL | Citation.js/CSL | 完整可用 | 格式正确≠文献真实 |
| 知识问答 | 模型+混合检索 | 本地模型；无则返回片段 | BM25 片段/笔记 | 无模型不冒充总结 |
| 数学验证 | SymPy 五能力 | 同 FULL | math.js/规则/抽样 | 只称样本证据 |
| Lean4 | 后端容器 | 同 FULL | 编辑/模板/词法/导出 | 只标 formal_pending |
| LaTeX | Tectonic+SyncTeX | 同 FULL | 编辑/模板/Bib/源码导出 | 无编译器不报成功 |
| Word/MD | Pandoc+后处理 | 同 FULL | MD 轻转换，Word 排队 | 不声称复杂保真 |
| 润色/翻译 | 星辰+本地规则 | 本地规则/模型 | 术语/符号/格式规则 | 规则≠润色完成 |
| 初审 | 五层 | 本地层，缺失显式 | 格式/一致性/基础符号 | 缺失层不算通过 |
| 教育数据 | 服务端隐私查询 | 同 FULL | 仅合法匿名快照 | 不绕过 k/审批 |
| 图表 | 服务端统计 | 同 FULL | DuckDB-Wasm/Arquero+Vega/ECharts | 绑定快照哈希 |
| 星辰 | Adapter 调用 | 自动停用 | 不调用 | 不隐式重复提交 |

恢复：离线对象使用客户端 ID；同步返回映射；文本冲突并列版本，集合合并，删除墓碑。恢复 FULL 后不自动重跑昂贵/敏感任务，先提示“升级重跑”。旧 run 保留用于差异比较。外部源用退避、熔断和缓存；来源不可用不是用户错误。

# 11. 数据与跨端

核心对象：`ResearchProject`、`ResearchQuestion`、`Asset`、`Document`、`CitationRecord`、`VerificationCase`、`FormalProject`、`ManuscriptProject`、`ReviewBatch`、`DatasetSnapshot`、`Run`、`Evidence`、`PublicationLink`。

```text
学生 DerivationSubmission → 发布副本 → VerificationCase

教师 ResearchBrief → 授权 → ResearchProject
```

# 12. HTML 原型范围

使用可信中文示例数据；按钮、Tab、筛选、弹窗、侧栏、运行抽屉和模式切换可操作，不用“功能建设中”填充主要页面。
