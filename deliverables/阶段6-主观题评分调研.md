## 三、深读发现（对落点决策有直接影响的代码细节）

### 3.1 huggingface/Math-Verify —— 沙箱判分引擎首选增强件
- API 极简：`from math_verify import parse, verify`；`verify(gold, pred, timeout_seconds=5, float_rounding=6, strict=True)`，要求两侧先经 `parse()`（含 `LatexExtractionConfig`/`ExprExtractionConfig`，可从一段文本中提取多个候选表达式取并集）。
- 非对称设计：gold 与 pred 位置不可互换（赋值化简、方程→区间的转换只对 pred 侧做），接入时**标准答案传 gold、学生答案传 pred**。
- 带超时（5s）与异常保护，天然适配沙箱内并发判分。
- README 自述在 MATH 数据集判分准确率高于 lm-evaluation-harness 与 Qwen 评测器。

### 3.2 matharena —— 三块可摘零件
1. `src/matharena/parser.py`（约 1130 行，MIT）：`extract_answer()`（最后一个 `\boxed` 提取，含「多个 boxed 取同行合并」「近似值优先让位精确解」「剥离单位/条件尾巴」等启发式）；`normalize_string()`（\left\right/\dfrac/unicode/align 环境全量归一）；`check_answers()`（SymPy `equals`，失败回退 `N(diff)<1e-10` 数值判等）；**`DelimitedAnswer` 类型化判等（区间开闭、集合无序、元组有序）**——高中数学「解集/区间/多空」场景刚需；`WarningType`（NONE/MINOR/POSSIBLE/MAJOR）解析警告分级。
2. `configs/judges/grading_scheme_creator.yaml`：rubric 生成 prompt——把官方解答拆成 **Checkpoints（≥4 分给主思路、≤3 分给常规步骤）+ Zero-credit items（未证明的猜想/复述题干记 0 分）+ Deductions（1/2 分或 cap 封顶）** 三段式；多解法时「平行 Chain 取最大子分、不跨链累加」；禁止批评官方解答、禁止过度拆分常规代数步骤。
3. `configs/judges/norm_judge.yaml`：judge prompt 核心——**替代解法映射到等价采分点**（不得因未按标准解法走而扣分）、零分项只在问题真实发生时施加、互斥采分点只计大者、中间结论必须有充分论证才给分、`<points>/<assessment>/<errors>` XML 输出、**分差>2 时再仲裁一轮并按 min 聚合**（保守倾向）。

### 3.3 openai/prm800k —— 449 行保守兜底判分器
- `grade_answer(given, truth)`：先 mathd 归一化字符串比对（宽），再 `_normalize`（去单位/百分比/混合数字转假分数）字符串比对，逐元素规则判分（**分数未约分即错、标准答案是整数时学生答案必须整数**），最后才允许 `sympy.simplify(diff)==0`。防放水规则集正是教育判分需要而评测判分器常缺的。

### 3.4 GradeLens —— 中文初批 prompt 与输出契约
- `/api/grade` 单题 JSON 契约：`transcribed_answer`（模型转录全文）/ `belongs_to_this_question`（归属硬约束）/ `score` / `full_score` / `deductions[]{point,deduct}` / `comment`。
- 两条已踩坑经验值得直接抄：① 整卷批阅存在**题目归属幻觉**（推理严谨但张冠李戴仍给高分），必须强制「先比对几何对象/字母点位再判归属，归属不符强制 0 分」；② LLM 输出吞反斜杠破坏 LaTeX，需 `_restore_latex` 类修复（我们存库/渲染同样会遇到）。

### 3.5 NeuroMark —— rubric 先行的中文工作流
- 「LLM 依据题目图片+提示词模板生成 Markdown 参考答案与**评分细则草稿** → 批阅按细则给分 → 人工复核」：证明「rubric 先行、教师可先审细则再审分数」在中文数学阅卷可行。其 rubric JSON 强约束（LaTeX 反斜杠双写转义、采分点分值和=满分、最小评分单元拆到小题）可直接搬进我们的题库 schema 设计。

## 四、推荐复用方案（含接入落点）

### 4.1 总体判断

现有「SymPy 沙箱 + LLM 初批 + 教师复核」架构方向正确，与调研到的最佳实践（Ishika0612 设计稿、STACK PRT、matharena 双轨判分）同构；缺的是四件事：**判分引擎对区间/集合/未化简形式的鲁棒性、rubric 先行的两段式初批、结构化扣分点输出契约、多判官仲裁与置信分流**。全部可用「摘零件」方式补齐，无需引入任何整套框架。

### 4.2 直接复用（拿代码/拿 pip 包，保留版权声明）

| 复用物 | 来源与 License | 接入落点 |
|---|---|---|
| `math_verify`（pip 包或源码） | huggingface/Math-Verify，Apache-2.0 | **SymPy 沙箱判分链路**：作为最终答案等价判定的主引擎。现有判分函数中，学生答案与标准答案先经 `math_verify.parse` 再 `verify(gold=标准答案, pred=学生答案, timeout_seconds=5)`；建议在独立线程/子进程跑以满足沙箱超时约束。Apache-2.0 允许闭源商用，需在 NOTICE 保留声明 |

**沙箱内多引擎判分顺序（建议）**：`现有判分逻辑 → Math-Verify.verify → matharena.check_answers → prm800k.grade_answer`；任一判对即对；全部判错但「数学归一化字符串相等」或触发 MAJOR 解析警告时，置 `needs_review=true` 转教师队列而非硬判 0 分。

### 4.4 不采用及理由

| 不采用项 | 理由 |
|---|---|
| STACK（qtype_stack）整套 | PHP + Maxima 技术栈，与我们 FastAPI+SymPy 无法整合；GPL-3.0 有传染性，禁止拷码。仅取 PRT 思想自研轻量采分点树 |
| AI-Marker-Suite 代码 | GPL-3.0 + 油猴挂机形态（自动填分到第三方平台），与平台化产品无关且有合规风险 |
| NeuroMark 整套 | Electron/TS 桌面应用形态不符；其价值（rubric prompt、工作流）已按思想吸收，MIT 允许抄但无必要 |
| GradeLens 整套（多模态直读图） | 我们的作答输入已是结构化文本/LaTeX，不存在「手写图片读题」环节；直接读图路线仅在其 OCR 前置环节有价值。仅采纳其输出契约与归属判定 prompt |
| 本地 PRM 模型（prm800k 训练范式） | 80 万步级标签用于训练 PRM，落地需 GPU 推理与蒸馏，成本远超当前初批 LLM rubric 方案；且 prm800k 已归档只读 |
| GraderFlow / AIPaper / Handwritten-Maths-Automarker / math-solution-grader 代码 | 均无 license（默认版权保留），法律上不可复用；且多为原型/设计稿，思想已覆盖 |
| matharena 全套评测运行时（runner/solvers） | 面向「批量跑 LLM 评测」而非在线判分业务，运行时复杂度（agent pool、checkpoint、多线程）远超需要 |
