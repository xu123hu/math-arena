## 1. Dify（langgenius/dify）——Celery 任务体系与运行记录表

**目录组织**：`api/tasks/` 55 个任务文件一任务一文件（命名即业务：`document_indexing_task.py`、`async_workflow_tasks.py`、`mail_*_task.py`…），celery worker 独立进程消费；API 进程只投递。

**WorkflowRun 运行记录表**（`api/models/workflow.py:791` 起，字段注释原文）——这是通用任务表设计的最佳参照：

```
status: running / succeeded / failed / stopped
inputs / outputs（text，JSON 串）
error（失败原因）
elapsed_time（s）、total_tokens、total_steps
created_by_role / created_by、created_at / finished_at
索引：workflow_run_triggerd_from_idx(tenant_id, app_id, triggered_from)、workflow_run_created_at_id_idx
```

要点：**运行记录与业务产物分离**（runs 表记过程，产物另存）；每次运行都留痕（可回溯、可审计）；triggered_from 区分调试/正式触发。

**异步工作流任务**（`api/tasks/async_workflow_tasks.py`）：celery `shared_task` 按订阅档位带不同重试策略与错误处理，调 `WorkflowAppGenerator`，用独立 `session_factory` 开会话、失败落库不抛穿。

**前端感知**：SSE 端点 `controllers/openapi/workflow_events.py`、`controllers/service_api/app/workflow.py`（`text/event-stream`）——**异步执行 + 事件流直播进度**，与我们的 classroom events 同构。

**不该抄**：多队列 worker 拓扑、插件/租户级任务隔离——单进程场景过度设计。

## 2. Open WebUI（open-webui）——同栈（FastAPI）定时任务 + 全站 socket 通知

**Automations 定时任务**（`backend/open_webui/routers/automations.py` + `models/automations.py:20,42`）——「定时出题」类需求的直接参照：

```python
class Automation:            # 自动化定义
    user_id / name
    data = JSON  # {prompt, model_id, rrule}
    is_active / last_run_at / next_run_at   # next_run_at 建索引扫描
class AutomationRun:         # 每次执行留痕
    automation_id / chat_id / status  # success | error
    error / created_at
```

路由层纪律（同文件 L45-109）：`check_automations_permission` → `check_automation_access` → **`check_automation_limits`（rrule 频率限额，对齐 ChatGPT Tasks「每小时最多一次」思想）** → CRUD + `/{id}/run` 手动触发。

**socket 通知**（`socket/main.py:340` `emit_to_users(event, data, user_ids)`）：按 `user:{id}` 房间定向投递事件，L1069 内部 `notification` 类型事件与业务事件分流——**「按用户房间推送」是我们若上 WebSocket 的交互蓝本**（一期可用轮询替代，接口形状对齐）。

**任务工具**（`utils/task.py`）：任务模型选择（小任务用轻量模型 `get_task_model_id`）、模板渲染——「标题生成等小任务用便宜模型」的思路我们已在用（`_start_title_task`）。

**不该抄**：Automation 的 rrule 全量实现（二期再引）；其 Svelte 前端组件（与我们 Vue 栈不同）。

## 3. LibreChat（danny-avila/LibreChat）——漏桶队列与文件异步处理

**漏桶队列**（`api/server/utils/queue.js`）：`_LB.queue` + 60 req/s 定间隔 `LB_QueueAsyncCall(asyncFunc, args, callback)` 串行消费，空了自动停 interval——**进程内最简速率闸**，适配「批量出题不冲垮 LLM 配额」的场景（我们现有 `asyncio.Semaphore(3)` 的进化方向：速率 + 并发双控）。

**文件异步处理**（`api/server/services/files/process.js:106` `enqueueDeleteOperation`）：删除/处理操作按「必要时入桶、否则直发」双路径，失败走 callback 错误通道——异步操作的统一入口模式。

**不该抄**：Mongo 生态（Job 模型在其 mongo indexes 中，与我们 PG 栈不同源）；Express 分层。

## 4. 工程决策三选一路径（直接复用 ＞ 改造复用 ＞ 自研）

| 决策点 | 选择 | 依据 |
|---|---|---|
| 任务执行器 | **改造复用**：自有 classroom 范式（`asyncio.create_task` + 独立 `background_session_factory` + DB 状态 + stale>90s auto-resume，stage_router.py:2340/2916）推广为通用 TaskRunner | 仓库内已验证最成熟；Dify 证明「执行与记录分离」思想可平移；不上 Celery（M1 决策 + 单进程量级） |
| 通用任务表 | **改造复用**：新表 `tasks`，字段语义抄 Dify `WorkflowRun`（status 四态/progress/error/elapsed_time/total_tokens/finished_at + kind + payload/result JSONB + idempotency_key）+ `teacher_tasks` 的 capability 命名 | 两表字段取并集，迁移路径清晰；教师域任务渐进映射不破坏契约 |
| 定时任务 | **自研创新（二期）**：Open WebUI Automation 的 `rrule + next_run_at 索引扫描` 模式，用 APScheduler 或 asyncio 周期扫表实现 | 本期主链路不含定时；模式已存档 |
| 完成通知 | **改造复用**：一期站内轮询（`/api/tasks?since=` 增量 + 红点），事件形状对齐 Open WebUI `emit_to_users` 语义，为二期 WebSocket 留接口 | 不引入 socket.io 新栈；通知降噪抄 ChatGPT Tasks（值得才推 + 限额） |
| AI 编排 | **直接复用**：Butler v2 Kernel（Planner→PolicyGate→Executor + 工具注册 + agent_runs 记账）——教师端已实跑 | 与 MS Copilot「Skills 清单 + 风险分级批准」范式同构，且是我们自己的代码 |
| 悬浮球交互 | **改造复用**：Notion「右下角悬浮 ↔ 侧边栏双形态 + 快捷键」→ Vue 组件 + 教师端 ButlerPanel 合并 | 教师端已有 ButlerPanel/⌘K；补学生端挂载点与双端统一 |
| 任务并发控制 | **改造复用**：`asyncio.Semaphore` 升级为 LibreChat 式漏桶（速率+串行）封装 | 出题批量场景实测需求 |
| 产物追溯 | **直接复用**：Dify「运行记录与产物分离」→ tasks.result 指向业务产物 + agent_steps/tool_invocations 已有记账 | 竞品差评反推的信任要求 |
