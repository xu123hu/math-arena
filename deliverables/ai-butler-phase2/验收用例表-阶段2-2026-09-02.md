## 〇、双轨定义与总则

| 轨道 | 验什么 | 证据方式 |
|---|---|---|
| **功能轨** | 输入→输出正确、接口/数据正确、异常路径有处理 | curl + SQL + 后台日志 |
| **体验轨** | 界面对标参考截图、内容真实、文案像人写的、每个按钮有真反应 | 页面截图 / 走查录屏 + 与参考图并排对比 |

总则：①任何「生成中」状态必须有进度或阶段文案，**禁永久转圈**；②任何失败必须可见原因+可重试；③所有产物自动落库且可在业务页找到；④AI 生成物按第 4 节基准库并排对比；⑤安全：任务/通知按 user_id 隔离，管家工具走 PolicyGate。

## 一、公共基建用例（G：tasks / TaskRunner / notifications，双端共用）

| 编号 | 轨道 | 用例 | 验证方式 | 通过标准 |
|---|---|---|---|---|
| G-1 | 功能 | 创建任务即落库：任一管家下单请求 → 返回 task_id，`tasks` 行 status=queued，payload 完整 | curl POST + SQL `SELECT status,payload FROM tasks ORDER BY id DESC LIMIT 1` | 行存在；幂等键重复提交不产生第二行 |
| G-2 | 功能 | **关页面任务不中断（本命题核心）**：创建生成任务后关闭浏览器/无任何连接，等待至终态 | 仅 curl 创建 → 无连接等待 → SQL 查终态 + 任务详情 curl | 任务到 succeeded，产物落库；全程无客户端连接 |
| G-3 | 功能 | **进程重启自愈**：任务 running 中 kill uvicorn → 重启 → 任务被重新拉起至终态 | bash kill + 重启 run_server.py → SQL 观察状态迁移 | 重启后 stale 扫描重拉任务；幂等不产生重复产物 |
| G-4 | 功能 | 失败可见可重试：构造必败任务（如非法 kp）→ tasks.status=failed 且 error 有原因 → 重试成功且不重复产物 | curl 创建/重试 + SQL + 日志 | 失败原因人话可读；重试走同幂等键 |
| G-5 | 功能 | 取消：queued/running 任务 → cancel → cancelled；终态任务不可取消 | curl POST /cancel + SQL | 状态机正确；已产出物不受损 |
| G-6 | 功能 | 权限隔离：用户 A 的任务 B 用户访问 → 404；教师任务学生不可见 | 两个演示账号 curl 互查 | 全部 404/403，无数据泄漏 |
| G-7 | 功能 | 任务列表增量接口：`GET /api/tasks?since=` 只返回增量与状态变化 | 两次 curl 对比 | 增量正确，排序稳定 |
| G-8 | 功能 | 并发与速率：同用户连发 5 个生成任务 → 并发上限/漏桶生效，无 LLM 配额击穿 | curl 连发 + 日志观察 | 超限任务排队不报错；LLM 调用速率受控 |
| G-9 | 功能 | 通知产生与降噪：任务终态产生 notifications 行；同任务不重复；做题沉浸模式（ai_mode=locked）静默；每日主动条数 ≤ butler_proactive_limit | SQL `SELECT * FROM notifications` + 场景实测 | 降噪三条全部命中 |
| G-10 | 体验 | 任务中心三态 UI：进行中（进度条+阶段文案）/成功（跳转按钮）/失败（原因+重试按钮）；空态有引导 | 截图 + 走查 | 与 ChatGPT Tasks 信息结构（截图 08）并排对比通过；无永久转圈 |
| G-11 | 体验 | 通知红点与列表：角标数字=未读数；点开列表；点单条跳产物；已读清零 | 录屏走查 | 与参考图（06 豆包侧栏/教师端既有铃铛）对比通过 |
