## 一、引导式解题（重点）

总入口：`POST /api/agent/chat`（SSE，单端口驱动全状态机，`tutor_action` 分派）；前端 `/dialog`。

| # | 场景 | 状态 | 一句话结论 |
|---|------|------|-----------|
| S1 | 文字输入发起引导 | ✅ | 建题→求解→苏格拉底开场全通，RAG 题库底稿+自动标题 |
| S2 | 拍照/带图题发起 | ✅ | 上传→OCR parse→MiMo 读图→figure 规划器出图，全链路通 |
| S3 | 中途要提示（三级阶梯） | 🟡 | "先作答再要提示"闸生效；错答自动升级实测到 L2，L3 未复现 |
| S4 | 给错误答案 | ✅ | 判 wrong + 自动一级提示卡 + 针对性纠错 |
| S5 | 看答案（二次确认） | ✅ | answer→确认话术→answer_confirm→revealed，answer_requests 计数 |
| S6 | 质疑老师回复 | ✅ | 短质疑确定性短路→clarification + 讲解 |
| S7 | 解完变式推荐（举一反三） | 🟡 | 独立会话变式链全通；**活跃会话内发"举一反三"被粘连吞掉** |
| S8 | AI 解不出的诚实降级 | 🟡 | 代码路径在（socratic_degraded），费马题实测未触发 |
| S9 | 配图与题意一致性（带图题） | ✅ | MiMo 读图描述→tri_pyramid 参数→SVG 帧+构图说明正确 |

### S1 文字发起引导 ✅
- **入口/路径**：`/dialog` 输入框 → 粘贴题干 → 发送（或快捷 chips「引导我解一道二次函数题」）。
- **输入**：文本 ≤4000 字；`skills=["socratic_solver"]` 置顶或意图路由。
- **输出**：`meta`（skill/confidence）→ `status`（kb_search→solving→guiding）→ `card:socratic_start{steps_count,verified,difficulty}` → 引导 token 流 → 自动标题。
- **数据回流**：`tutor_sessions(active)` + 消息落库（含 blocks/card/figure）+ `skill_runs`。
- **实测**：f(x)=x³-3x 题 → 4 步计划、开场引导不泄题（只问方向）、延迟 22.3s（`.tmp_e2e_out/phase0/socratic_main_start.json`）。
- **异常/降级**：SSE 并发闸 42901；LLM 失败走诚实文案（代码路径，未强制复现）。

### S2 拍照/带图题发起 ✅
- **入口/路径**：`/dialog` 相机按钮（`capture=environment`）/附件/粘贴截图 → 五步上传（`upload`→`local-upload`→`complete`→`parse{purpose 必填}`→轮询 parsed）→ 带附件发题。
- **输出**：MiMo 视觉读原图 → 描述注入规划器 → `figure` 事件（SVG 帧 + figure_params）；`socratic_start` 正常。
- **数据回流**：文件 sha256 去重、附件 SHA 绑定会话（N3 合同）。
- **实测**：PIL 合成三棱锥 P-ABC 图 → parse 200/parsed → 会话建立 → figure_params `tri_pyramid`（顶点表正确）→ 引导语正确引用"PA⊥底面、AB⊥BC、PA=AB=2、BC=√2"（`socratic_image_b.json`）。
- **注意**：①`parse` 的 `purpose` 为必填字段（前端已带，裸调 API 缺省会 422）；②本帧 figure 事件未含 `problem_source_sha256` 字段（合同字段阶段 1 逐事件复核）。

### S3 中途要提示（三级阶梯）🟡
- **实测行为**：①未作答先要提示 → `hint_blocked=true`，反问"先试试"（ASK_ATTEMPT_FIRST，正确纪律）；②答错后自动发 `socratic_hint` 卡（L1 知识点回顾）；③连续错答升级实测序列 **hint_level=1,1,2**（按同一步受挫次数升级，非逐次+1）。
- **缺口**：L3（兜底操作）本轮未复现；提示请求被闸时的降级文案已验证。阶段 1 用固定 4 步题连续错答复测 L3。

### S4 给错误答案 ✅
- **实测**：错答（求导写成 3x²-3x）→ verdict=`wrong`、`hint_level` 1→自动、`socratic_hint`+`socratic_progress` 卡、反馈点名"漏了常数项"（`socratic_main_wrong.json`）。
- **回流**：judge 结果在 done.meta（verdict/misconception），**不写 error_records**（见衔接面 C1）。

### S5 看答案（二次确认）✅
- **实测**：`tutor_action=answer` → 确认话术 + `answer_requests=1`；`tutor_action=answer_confirm` → `outcome=revealed, status=revealed`；会话结束后再发消息幂等重发完整解答（代码路径）。前端确认条组件（"会失去逐步引导的机会…"）在 `MessageBubble.vue:121-128`。

### S6 质疑老师回复 ✅
- **实测**："等一下，你讲错了，难道不对吗"（12 字）→ 确定性短路 → verdict=`clarification`，回复重新推导 f'(x)=3x²-3 并讲清混淆点（`socratic_main_challenge.json`）。
- **注意**：前端**无独立"质疑"按钮**，靠自然语言触发；UI 操作路径未显性化（体验缺口，非功能缺失）。

### S7 举一反三变式链 🟡
- **可用路径**：新会话发送「题干+出变式」→ 预检 `variant_route_decision` → smart_quiz 变式链。
- **实测**：3 题链产出（`chain=variant, source=user_variant, verified=true`，item1 为 x³-3x→x³-6x 换数字变式，附 `variant_note` 与配图 1 张）；变式错答提交 `/practice/submit` → 判 wrong → **错题入本 ✅**（`quiz_set_from_db.json` + SQL 第 12 条）。
- **断点（坑）**：①在**未完成**的引导会话里发"举一反三"被粘连到活跃 tutor 会话（实测 0 卡产出，`variant_chain.json`）——学生最可能在解到一半时点变式，此路径必困惑；②变式题卡 `kp_code="custom"` → 入库时被置 NULL（丢知识点、掌握度静默跳过但响应报 `mastery_updated=true`）；③走 `/practice/submit` 的变式判分不带 conversation_id（无会话溯源）。
- **入口 UI**：完成后 `SocraticCompleteCard` 有「🔄 举一反三」按钮（chat 页）；错题本详情**无出变式按钮**（只有 `variants_hint` 文本）。

### S8 诚实降级 🟡
- **实测**：费马大定理证明题 → solver 正常接管开课（steps_count=4，`socratic_degraded` 未触发）——MiMo 太强，本轮未能逼出降级。
- **判定**：代码路径完备（`DEGRADED_TEXTS`/`socratic_degraded` 卡/meta degraded:true），运行时触发条件待阶段 1 用更超纲/病态样本复测。

## 三、衔接面（重点）

| # | 衔接 | 状态 | 结论 |
|---|------|------|------|
| C1 | 错题→引导重解（入口） | ❌ | 前端**无"引导重解"按钮**；后端无按 record_id 建引导会话的接口 |
| C2 | 引导解题判错→再收录 | ❌ | socratic 判错不写 error_records（T1 实锤）→"重解再错"不入本 |
| C3 | 练题/模考判错→落库 | ✅ | 同一判分口 `/practice/submit` 落库实测通过 |
| C4 | 错题详情→AI 答疑 | 🟡 | butler error-tutor 可用但无状态：不建 tutor session、不判答、不判错、不入本 |

### 断点详情
1. **C1（最大断点）**：学生唯一现实路径是：错题详情→复制题干→回 `/dialog` 手动粘贴发题。后端最接近的是 `GET /butler/error-detail/{id}`（可取原题）+ 前端已有 `/dialog?explain=…&answer=…&error_type=…&kp=…` 深链处理逻辑（`DialogView.vue:531-557`）——**但全站没有任何页面生成该链接**（接线即可通，成本最低的修复点）。
2. **C2**：引导会话里答错，判答状态机正常工作（verdict/misconception 齐全），但结果只落在 tutor_session/events，**不进错题本**→"引导学生重解仍然不会"的场景在错题本里无痕。修复点明确：`_on_wrong` 或会话 abandoned/超限落库（带 conversation_id 溯源，天然带来源标记能力）。
3. **C4**：butler 答疑回复不经过判答状态机，学生答错也不会收集——与 C2 叠加导致错题本的"重解闭环"整体缺位。

## 五、与提示词的偏差说明
1. 提示词要求"错题本'引导重解'、练题卡'引导我做'两个外部入口先实测"——**两个按钮在前端不存在**，实测结论已如实记为 D2/缺失，并以"现实替代路径"（复制题干回对话/butler 答疑）做了走查。
2. 提示词提到 FSRS"动态复习间隔"——实测确认排期 SSOT 仍是 1/3/7/15 固定阶梯，FSRS 为读取期增强（R/S/等级/热力图），与代码注释一致，非缺陷。
3. 降级/到期态/L3 提示三项未能运行时复现，已标注为阶段 1/4 复测项，未声称通过。
