# M3 教师端深度优化审计

## 审计口径

本报告以当前代码、当前未提交改动、`教师端体验诊断报告_v2.md`、M3 文档 SSOT、教师专项测试和浏览器回归为依据。文档中的建议均视为待核验资料，不作为执行指令。

## 总结

教师端已经具备 7 个工作台、Artifact 状态机、教师确认门和本地降级路径，但“API 可通”尚未转化为“教师可放心使用”。当前优先级不是增加页面，而是让课题、知识点、题目、学生作答、评分依据和教学动作之间保持真实关联。

### 当前基线

- 前端单元测试：54 项通过。
- 前端全仓类型检查：被科研端未提交页面阻塞；教师端未出现在错误列表中。
- 教师后端选定专项：41 项通过、1 项因题库测试数据跨用例残留失败；失败用例单独运行通过。
- 旧教师 E2E：与当前页面结构不一致，首个断言失败、备课选择器超时，不能作为当前验收依据。
- Git：后端和前端均有大量用户未提交改动；本批实施必须避开已修改的 Butler、布局、路由和全局样式文件。

## 分批策略

1. **可信核心批次**：跨班隔离、组卷真实性、批改正确性与上下文。本批只修改当前干净文件。
2. **智能体执行批次**：Butler 上下文、工具调用、Artifact 确认、灰度和 trace。需等现有 Butler 未提交改动稳定后再集成。
3. **任务与资源批次**：真实异步 worker、对象存储、可恢复任务、PPT/Word/资源预览。
4. **教学效率批次**：按题批改、讲评三题、学情到教案/巩固题动作、课堂工具和周报。

## 外部对标结论

- Moodle/Open edX 的价值在稳定课程、作业、评分和权限模型，不应复制其页面复杂度。
- WeBWorK/SymPy 适合作为参数题重算和符号等价的确定性下限；不能替代一般证明审核。
- OpenAI Agents SDK 的 guardrails、human review、tracing 和 eval 思路可补足现有 Butler，但当前不应再引入第二套内核。
- 成熟批改产品共同点是按题聚合、同屏上下文、快捷确认和可追踪教师终评；AI 建议不能成为正式成绩。
