# 学生错题本配图与正解持久化设计

## 目标

让学生错题本中的原题配图可靠显示；对确有图形依赖的数学题，正解首次生成时附带可用示意图；同一错题的正解只生成一次并持久化，后续访问直接读取。

## 现状与根因

- `ErrorRecord.image` 是自由 JSON 列表。题库、拍照和动态图形三个入口分别写入 URL、data URI、GeoGebra 对象或图形帧对象，缺少统一的错题快照契约。
- `DynamicFigureViewer` 仅把字符串渲染为静态图片，未知对象既不会转换为可显示源，也没有错误回退；因此会输出破损的“题目配图”图片。
- `butler.skills.error_detail` 每次 GET 都调用模型生成 `generated_answer`；`ErrorRecord` 没有正解或正解配图列，所以刷新页面必然重新生成。

## 设计

### 1. 错题资源快照契约

新增后端纯函数，将任意历史或新写入的 `image` 项规范化为以下仅两类值：

- 静态图片：`{ "type": "image", "src": "data:image/..." | "https://...", "alt": "题目配图" }`
- 交互图：现有 `{ "type": "ggb", "view": "2d" | "3d", "commands": [...], "caption": "..." }`

接受并转换历史字符串、`{data_uri: ...}`、`{frames:[{data_uri: ...}]}` 和合法的 URL 对象；不可用值丢弃并记录结构化警告。详情接口返回规范化结果；新错题收录时也以该函数保存。前端查看器只渲染这两种契约，并为单张图片加载失败显示“配图暂不可用”，不再产生破损图标。

### 2. 正解与正解图的持久化

在 `error_records` 新增：

- `generated_answer`：已核验的 Markdown/LaTeX 正解文本，可空。
- `solution_figure`：上述资源快照契约的列表，可空，默认空数组。
- `solution_generated_at`：首次成功生成的时间，用于审计。

`GET /api/butler/error-detail/{record_id}` 的规则是：已有 `generated_answer` 时不调用模型，直接返回缓存；没有时在同一请求内生成正解、按题目是否需要图形决定是否调用现有图形规划/渲染能力，然后原子写回记录并提交。生成正解成功但图形失败时，仍保存正解并返回空图；图形失败不能触发正解重生成。

“需要图形”由题干的图形语义与已有原题图共同决定，且只对几何、解析几何及明确“如图/图中”依赖的题触发。普通代数、概率和数列题不生成装饰性图片。图形生成只使用题干中已知关系，不能凭空补充条件；无可信图形参数时返回空图而非伪造示意图。

### 3. 页面行为

错题详情在取得基础详情后并行请求错因与正解。正解接口响应若含 `solution_figure`，在正解文本上方显示“正解示意图”；原题图与正解图分开，保持各自的加载错误状态。已缓存正解不再显示“AI 生成中”。保留“重新生成动态图形”作为学生主动操作，但它只影响原题交互图，不会覆盖已保存的正解和正解图。

### 4. 兼容与安全

- 历史记录不做全表迁移或批量模型调用；首次访问时按需规范化并读取，只有用户主动打开且缓存为空时才生成正解。
- 仍以 `record.user_id == current_user` 做访问校验；所有写回均限于该记录。
- 并发打开同一记录时通过行级锁/条件更新保证至多一次正解生成；第二个请求读取首个请求保存的结果。
- 正解内容继续由 `MarkdownView` 渲染 LaTeX，避免原始公式文本直出。

## 验收标准

1. 历史字符串、图形帧对象和新的资源对象均在错题详情正确显示，未知或失效资源显示可读空态。
2. 含“如图”的立体几何错题首次打开后显示原题图和正解示意图；普通非图形题不生成额外图。
3. 同一错题连续请求两次正解接口，模型生成函数只调用一次，第二次返回完全相同的持久化文本与图形。
4. 正解图生成失败时，正解文本仍保存并在下次打开时直接读取。
5. 学生不能读取或生成其他用户错题的正解与资源。
